# פיתוח מאובטח — התאמה להנחיית מערך הסייבר הלאומי

מסמך זה מתעד את התאמת הפורטל להנחיה **"הקפדה על כללי הפיתוח המאובטח באתרי Web"**
(אגף הגנה טכנולוגית, מערך הסייבר הלאומי, TLP|CLEAR, 01/09/2026) ולעקרונות OWASP.

## 1. מה ההנחיה דורשת

האירוע שתואר בהנחיה נגרם משתי תקלות פיתוח/הפעלה:

1. **חשיפת ספריית ה-git** של האתר.
2. **הטמעת מפתחות API** באופן שהיה נגיש לתוקפים.

ומכאן שלוש דרישות: פיתוח לפי מתודולוגיות מוכרות; לוודא שכלי הפיתוח (git, מפתחות API)
אינם חשופים; ולהיעזר במקורות (OWASP Top 10 / ASVS / WSTG).

## 2. מצב בפועל — נבדק על סביבת הייצור

| בדיקה | תוצאה |
|---|---|
| `/.git/config`, `/.git/HEAD`, `/.git/index`, `/.git/logs/HEAD` | **404 — לא חשוף** |
| `/.env`, `/.env.local` | **404 — לא חשוף** |
| מפות מקור (`*.js.map`) | **403 — לא מוגשות** |
| סריקת חבילת הלקוח (≈414KB, 5 chunks) | **נקי** — ללא מפתחות API, מחרוזות חיבור, טוקנים או מפתחות פרטיים |
| שמות משתני סביבה שרתיים בחבילת הלקוח | **absent** (DATABASE_URL, CMS_*, STAGE_PASSWORD, RESEND_API_KEY וכו') |
| קבצי `.env` במעקב git | **אין** (רק `.env.example` ללא ערכים) |
| `.vercel/` במעקב git | **אין** |
| סודות מוטמעים בקוד המקור | **אין** (סריקת דפוסים: מפתח פרטי, postgres://user:pass@, AIza…, sk-…, re_…, xox…, AKIA…, ghp_…) |
| כותרות אבטחה (CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy) | **כולן נשלחות** בכל סוגי המסלולים |
| הגנת Edge | Vercel Firewall / Attack Challenge Mode פעיל |

> הערה מתודולוגית: בדיקה באמצעות `curl` מחזירה 403 עם `x-vercel-mitigated: challenge`
> (מנגנון ההגנה מפני בוטים) ולכן אינה אמינה לאימות כותרות. האימות בוצע מדפדפן אמיתי.

## 3. בקרות במימוש (OWASP Top 10)

- **A01 בקרת גישה** — כל מסלולי ה-CMS/API מאמתים session בצד השרת; ניסיון גישה ללא הרשאה מוחזר 401.
- **A02 כשלים קריפטוגרפיים** — TLS בתעבורה + HSTS; הצפנה במנוחה (Neon); סיסמאות CMS נשמרות כגיבוב SHA-256 בלבד; עוגיות `httpOnly` + `secure` + `SameSite`.
- **A03 הזרקה** — כל שאילתות ה-SQL פרמטריות (`pg` placeholders); נבדקו SQLi, path traversal ו-null byte.
- **A05 תצורה שגויה** — כותרות אבטחה מלאות; מפות מקור מושבתות; ספריות פיתוח אינן נפרסות.
- **A07 זיהוי ואימות** — הגבלת קצב על ניסיונות התחברות ל-CMS.
- **A09 רישום וניטור** — פער ידוע: אין חיבור ל-SIEM/SOC ארגוני (ראו §5).

## 4. בקרת רגרסיה אוטומטית

נוספה בדיקה החוסמת חזרה של בדיוק התקלות שבהנחיה:

```bash
npm run security:check
```

הבדיקה נכשלת (exit≠0) אם: קובץ `.env` נכנס למעקב גרסאות, `.vercel/` נכנס למעקב,
`.gitignore` אינו מכסה נתיבים רגישים, נמצא סוד מוטמע בקוד, חסרה כותרת אבטחה
ב-`next.config.js`, או הופעלו מפות מקור לייצור. ניתן להריץ גם מול כתובת חיה:

```bash
npm run security:check -- https://mapi-customer-portal-poc.vercel.app
```

מומלץ לשלב אותה כשלב חובה בצנרת ה-CI לפני כל פריסה.

## 5. פערים לסגירה לפני ייצור מלא

1. **הלבנת קבצים (CDR/Sandbox)** — הטפסים מיועדים לקבל צרופות (קובצי GIS, מפות מדידה). כיום אין תהליך הלבנה.
2. **ניטור** — חיבור ל-SIEM/SOC ארגוני.
3. **הזדהות** — מעבר ל-SSO ארגוני לממשק הניהול במקום שם משתמש וסיסמה.
4. **הפרדת סביבות** — סביבות הבדיקות והייצור חולקות כיום מסד נתונים אחד.
5. **מיקום מידע** — אזור הריצה בפועל הוא פרנקפורט (מחוץ לישראל); נדרשת הכרעה.
